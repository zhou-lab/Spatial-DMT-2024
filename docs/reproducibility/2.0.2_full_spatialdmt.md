## Scope

repository documentation and source selected by Git's normal include/exclude
rules. It uses the complete published Spatial-DMT E11#1 DNA library and its
matched RNA library, not a subset or smoke fixture.

## Problems found and corrections

### GNU Parallel stream corruption diagnostics

The first production-equivalent trim attempt used GNU Parallel `--pipe` and
emitted allocator failures such as `munmap_chunk` and `double free` once per
block while returning status zero. Running the worker directly on the same node
and input succeeded, isolating the problem to the byte-stream launcher.

The trim rule now uses `tools/stream_parallel.py`, a bounded Python coordinator
that reads newline-aligned blocks, limits active workers, preserves block
numbering, and terminates siblings while returning nonzero when any worker
fails. A two-million-pair Slurm fixture completed in three blocks with zero
allocator diagnostics. Its aggregate counters exactly matched a direct
single-worker baseline, and all six decompressed FASTQ categories were
byte-identical. Two test-harness issues encountered during that comparison
(unordered stats rows and an overly broad output glob) were corrected before
the final comparison; neither was a pipeline defect.

### BISCUIT lambda pileup numerical overflow

Full-depth lambda pileup aborted with:

```text
a or b too big, or MAXIT too small in betacf: Numerical result out of range
```

The full lambda BAM contained 19,611,079 mapped records concentrated on the
48.5-kb reference. Release 2.0.2 now deterministically caps only the mapped
records supplied to lambda pileup, keeping records with the same read name
together. Full-BAM alignment, mapping, and duplication metrics are unchanged,
and `qc/table/<sample>_lambda_pileup_sampling.tsv` records the original count,
sampled count, fraction, and configured cap.

An isolated rerun sampled 2,002,082 records from 19,611,079 (fraction
0.101983169819). BISCUIT pileup, tabix indexing, all-cytosine conversion, CpG
strand merging, and YAME packing then completed successfully in Slurm job
`25458759`.

### Slurm environment export

The first resumed genomic pileup (`25507598`) failed before computation with
`ERROR: missing tool: yame`. The controller used the fresh environment, but a
restrictive parent Slurm export policy did not reliably propagate its `PATH`
to every cluster-generic rule job. This was node-dependent: earlier rule jobs
had found YAME, while this allocation did not.

The checked-in Slurm profile now passes `sbatch --export=ALL` explicitly. A
probe submitted with `SLURM_EXPORT_ENV=NONE` then resolved YAME, BISCUIT,
BBTools, STAR, and Python from the new Micromamba prefix and completed as job
`25513548`. A regression test requires the explicit export setting.

### Pileup executable resolution

After environment export was corrected, the batched pileup helper still
treated a bare executable name such as `yame` as a filesystem path. It now
resolves bare command names through `PATH` and continues to accept explicit
paths. A regression test exercises this behavior.

### Fragmented cluster capacity during resume

The corrected 69-CPU pileup initially remained pending because no node had 69
free CPUs, although the partition had idle CPUs in smaller fragments. A 48-CPU
resume command was prepared, but the final successful pileup retained the
configured 69 CPUs once a suitable node became available. Job `25519388`
completed in 25:58 without changing release defaults.

### Optional unmatched alignment contract

The first final-validation attempt incorrectly required an unmatched BAM even
though release 2.0.2 performs FASTQ-backed structure-failure and whitelist-miss
decomposition by default. Unmatched genomic alignment is intentionally enabled
only with `UNMATCHED_DIAGNOSTICS_WITH_BAM=true`. The README, workflow comments,
and validation harness now use the same contract. The final deliverable also
retains the Lambda pileup sampling manifest so control-depth provenance is not
lost when intermediates are removed.

## Final validation

The initial dependency-based resume controller was Slurm job `25458761`; it
completed the patched lambda pileup and spatial/BISCUIT scans but exited after
the pileup executable-resolution failure. A canceled capacity experiment and
a stale-lock attempt did not run analysis. After the stale lock was removed,
controller `25519365` completed all six remaining workflow steps in 1:56:52.
Its genomic pileup, YAME summaries, curated metrics, HTML reports, and final
copy jobs all completed successfully.

The final validator, Slurm job `25556403`, completed successfully in 46:28. It
checked:

- exact DNA input/trim accounting and release metadata;
- gzip integrity for all six trim output categories;
- `samtools quickcheck` for merged, lambda, and per-pixel BAMs, plus the
  unmatched BAM when optional BAM-backed diagnostics are enabled;
- YAME readability for genomic and lambda `.cg` files;
- nonempty RNA matrices, reports, MultiQC data, and final deliverables;
- all repository unit tests in the fresh environment; and
- a no-op dry run of the complete `final_output` target.

The validated run contains 2,500 per-pixel BAMs and an indexed genomic YAME
matrix with 2,500 columns and 21,867,837 CpG rows. The final genomic `.cg` is
816,859,442 bytes. The STARsolo raw matrix is 90,413,924 bytes; STAR received
47,022,549 reads, of which 31,584,401 mapped uniquely (67.17%). Full-depth
lambda alignment retained 19,611,079 mapped records, and its pileup sampling
manifest records 2,002,082 selected records with fraction 0.101983169819.

All six trim FASTQs passed full `gzip -t`; merged, lambda, and all per-pixel
BAMs passed `samtools quickcheck`; genomic and lambda matrices passed `yame
info`; both HTML reports were valid and nonempty; and the final Snakemake dry
run reported `Nothing to be done`. A current SmC-seq DNA+RNA dry run from empty
output directories also resolved the complete 21-rule DAG. The earlier 2.0.1
clean-room audit remains the end-to-end execution test for the SmC-seq branch;
the shared 2.0.2 stream launcher is covered by a byte-identical two-million-pair
fixture and failure-propagation tests.
